# Источники и трассировка учебного контента

Документ закрывает требование ТЗ: опора на **CWE**, **OWASP Top 10**, **APWG** и общие рекомендации по безопасности.  
Связь **не жёсткая сертификация**, а **педагогическая трассировка**: сценарии спроектированы в терминах реальных классов угроз.

## OWASP Top 10 (релевантные категории)

| Категория (обобщённо) | Где в продукте |
|----------------------|----------------|
| **A01 — Нарушение контроля доступа** | Офисный чат: запросы «IT» на пароли вне каналов; обход процедур перевода средств (BEC). |
| **A02 — Криптографические сбои** | Публичный Wi‑Fi: открытые сети, отсутствие проверки SSID/учётных данных у персонала. |
| **A03 — Инъекции** | Косвенно: фишинговые формы и поддельные страницы входа как вектор кражи данных (не исполняется реальный эксплойт). |
| **A04 — Небезопасный дизайн** | Сюжеты «срочно / только сейчас», давление на пользователя — учебная иллюстрация **unsafe design** в социнженерии. |
| **A05 — Некорректная конфигурация** | Выбор сети и доверие к визуально «правильному» SSID без проверки. |
| **A07 — Ошибки идентификации** | Подбор/повторное использование паролей после утечки, смешение личного и корпоративного. |
| **A09 — Нарушение журналирования** | В симуляции упоминается реакция (тикет в SOC) как правильная практика после инцидента. |

## CWE (примеры соответствий)

| CWE | Тема | Модуль / контекст |
|-----|------|-------------------|
| **CWE-20** Некорректная валидация входных данных | Доверие к поддельным письмам и ссылкам без проверки отправителя | Дом, почта |
| **CWE-451** Подмена интерфейса пользователя | Поддельные страницы входа в Wi‑Fi / фишинг | Wi‑Fi, почта |
| **CWE-798** Хардкод учётных данных | Контраст: учим **не** использовать общие/простые пароли и **не** слать секреты в чат | Офис, «выбор действия» |
| **CWE-306** Отсутствие аутентификации | Открытая сеть без шифрования как риск перехвата | Wi‑Fi |

## APWG (фишинг и мошенничество)

- **Поддельные банковские и сервисные письма**, срочность, имитация доставки и зарплатных реквизитов — линия модулей **Дом / почта**.
- **SMS/мессенджерные сценарии** (смishing-настроение) — шаги домашнего арка в `scenario_api` / narrative.

## Скимминг и платежи

- Отдельный модуль **POS/ATM** согласуется с рекомендациями **PCI DSS** и банковских программ по **физической защите терминалов** (проверка ридера, PIN-privacy) — в учебной форме без реальных атакующих устройств.

## Как использовать документ при защите

1. Показать **конкретный шаг сценария** → назвать класс угрозы (OWASP/CWE/APWG).  
2. Подчеркнуть: в продукте **нет реальных вредоносных файлов и эксплойтов**, только **симуляция последствий** и **разбор решений**.
